# Twitch Chat Overlay

Local browser-source chat overlay for OBS that combines Twitch chat and YouTube live chat into one customizable HTML overlay.

## Project Shape

- `server.js` is a small Node.js HTTP helper. It serves the overlay/control pages, persists shared config, emits server-sent events, and can proxy/poll YouTube web live chat.
- `stream_chat_overlay.html` is the main OBS/browser overlay. It contains the UI, rendering CSS, settings panel, Twitch IRC WebSocket client, YouTube Data API client path, demo messages, and local persistence.
- `control.html` is a simpler external control page for updating stream targets while OBS stays pointed at the same local URL.
- `start-overlay.bat` stops any prior helper instance, starts `server.js`, and opens the control page.
- `overlay-config.json` is ignored local runtime config and may contain credentials. Copy `overlay-config.example.json` to create it manually, or let the helper create it after the first save.
- `overlay-server.pid` is generated by the running helper.

## Running

From this folder:

```powershell
node server.js
```

Then open:

- Control page: `http://localhost:8080/control`
- OBS browser source: `http://localhost:8080/stream_chat_overlay.html`

The helper binds only to IPv4 loopback, starts at port `8080`, and tries later ports if the port is already busy. `start-overlay.bat` wraps the common Windows workflow.

## Runtime Model

The overlay has two operating styles:

- Local helper mode on `localhost` or `127.0.0.1`: `stream_chat_overlay.html` fetches `/api/config`, subscribes to `/api/events` for config changes, and subscribes to `/api/chat` for helper-emitted YouTube messages/status.
- Standalone/browser mode: settings live in `localStorage` key `schat5` and selected non-private settings are mirrored into the URL hash so an OBS URL can carry appearance and connection settings.

Private OAuth access tokens (`ttoken`, `gtoken`) are intentionally excluded from the URL hash, but still stored in browser `localStorage`.

## Security Notes

- Never commit `overlay-config.json`; it is ignored because it can contain a YouTube API key and stream-specific settings.
- Restrict any YouTube API key to the required API and appropriate browser/referrer usage in Google Cloud, and rotate a key if it has been exposed.
- Keep the helper local. It binds to `127.0.0.1`, rejects cross-origin state changes, and is not designed for internet-facing hosting.

## Chat Sources

Twitch:

- Uses `wss://irc-ws.chat.twitch.tv:443`.
- Can connect anonymously with a `justinfan...` nick, or with a Twitch OAuth token.
- Requests Twitch IRC tags/commands for badges, username colors, emotes, and room metadata.
- Loads Twitch global/channel badges and optional BTTV global/channel emotes.

YouTube:

- The overlay itself can use the YouTube Data API with either an API key or Google OAuth token.
- The helper server also includes a web-chat polling path that scrapes YouTube initial data for an Innertube continuation, polls `youtubei/v1/live_chat/get_live_chat`, normalizes messages, and pushes them to the overlay via SSE.
- YouTube avatar/custom emoji images are proxied through `/api/img` with a host allowlist.

## Development Notes

There is no package manifest yet. The server currently depends only on Node built-ins plus the global `fetch` available in modern Node.

Suggested smoke test after changes:

1. Start `node server.js`.
2. Open `http://localhost:8080/stream_chat_overlay.html`.
3. Use the built-in Twitch/YouTube demo buttons and static test messages.
4. Open `http://localhost:8080/control`, save a harmless config change, and confirm the overlay receives it without reload.
